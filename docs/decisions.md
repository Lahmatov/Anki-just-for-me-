# Решения

## Открытые — блокируют старт

### D-1. Есть ли Mac? 🔴
Определяет вообще всё. Нативное iOS-приложение собирается только в Xcode на macOS.
- **Mac есть** → SwiftUI, всё ключевое (произношение, аудирование, офлайн) бесплатно и на устройстве.
- **Mac нет** → PWA. Работает, но проверка произношения уезжает в платный облачный API,
  а озвучка и распознавание в iOS Safari заметно хуже и капризнее.

### D-2. Какой iPhone и какая iOS? 🔴
- iOS 26+ на iPhone 15 Pro и новее → доступны `SpeechAnalyzer` (лучшее распознавание) и
  `FoundationModels` (бесплатная локальная LLM для проверки свободных ответов).
- iOS 17–18 → старый `SFSpeechRecognizer`, без локальной LLM. Тоже нормально, просто скромнее.

### D-3. $99/год Apple Developer — платим? 🔴
- **Нет** → раз в 7 дней пересобирать через Mac. Для «для себя» терпимо, но это ритуал навсегда.
- **Да** → сборка живёт год, TestFlight (ставится по ссылке, без кабеля), синк через iCloud.
Локальные напоминания работают в обоих случаях.

### D-4. Платить ли за пофонемную оценку произношения?
Azure: ~$1.30 за час аудио, бесплатный тир 5 часов/месяц. При 30 записях в день это
**~$1.5/мес и скорее всего $0** — укладывается в бесплатный тир.
Без этого on-device проверка будет мягкой и местами будет хвалить незаслуженно.
Предложение: делать на бесплатной основе, платный разбор подключить в Итерации 3 по кнопке.

## Принятые

- **P-1.** Алгоритм по умолчанию — FSRS-6. SM-2, Leitner и Cram доступны как альтернативы,
  выбираются на уровне набора.
- **P-2.** Модель «запись → несколько карточек» (как в Anki). Не экономим на этом в MVP.
- **P-3.** Формат обмена — свой JSON (`ajfm-deck`), не `.apkg`. CSV — запасной вход.
- **P-4.** «Выучено» = карточка зрелая, интервал ≥ 21 дня. Единая метрика для всех наград.
- **P-5.** Награды привязаны к результату, не ко времени и не к количеству сессий.
- **P-6.** Экспорт базы в JSON делаем в Итерации 0, до всего остального.
- **P-7.** Никакого бэкенда, аккаунтов и подписок.
