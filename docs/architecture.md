# Архитектура

## Стек

- **SwiftUI**, таргет iOS 17+ (а всё, что завязано на `SpeechAnalyzer` и `FoundationModels`,
  включается только на iOS 26+ через `if #available`).
- **SwiftData** — локальная база. Никакого сервера.
- **AVSpeechSynthesizer** — озвучка, офлайн.
- **SpeechAnalyzer / SFSpeechRecognizer** — распознавание, on-device.
- **AVAudioEngine** — запись голоса.
- **UNUserNotificationCenter** — локальные напоминания (работают и без платного аккаунта).
- Опционально: **Azure Pronunciation Assessment** — пофонемный разбор по кнопке.
- Опционально: **FoundationModels** (iOS 26+) — проверка свободных ответов, генерация примеров.

Внешних зависимостей минимум: только FSRS (свой порт или SPM-пакет) — всё остальное системное.

## Модель данных

Ключевое решение, скопированное у Anki и определяющее всё остальное:
**«запись» (note) ≠ «карточка» (card)**.

```
Folder            папка, может вкладываться в папку
 └── Deck         набор («Breaking Bad S03E05»)
      └── Note    одна словарная единица: term, translation, ipa, example, exampleTranslation, tags, audioRef
           └── Card   один способ спросить эту единицу
                      type: recognition | recall | listening | spelling | pronunciation | cloze
                      due, interval, reps, lapses, state
                      schedulerState: JSON под конкретный алгоритм
Review            журнал: cardId, timestamp, grade, timeSpent, algorithm, inputPayload
RewardContract    цель (150 зрелых слов) + награда («диск с игрой») + статус
Achievement       разблокированные ачивки
```

Почему так: одно слово порождает 2–6 карточек, у каждой свой независимый интервал —
ты можешь отлично узнавать слово и при этом не уметь его писать. Если сэкономить на этом
разделении в MVP, переделывать придётся всё.

Из этого следует **burying сиблингов**: показав сегодня одну карточку слова, остальные
карточки того же слова откладываем на завтра.

## Движок повторений

```swift
protocol Scheduler {
    var id: SchedulerID { get }
    func nextReview(card: CardState, grade: Grade, now: Date) -> CardState
    func previewIntervals(card: CardState, now: Date) -> [Grade: TimeInterval]
}
```

Реализации: `FSRS6Scheduler` (дефолт), `SM2Scheduler`, `LeitnerScheduler`, `CramScheduler`
(режим Quizlet Learn). Алгоритм выбирается **на уровне набора**, не глобально — за сериалы
можно взять FSRS, а за срочную лексику к поездке — Cram.

Состояние карточки — одна структура `ReviewState` с общими полями (состояние, срок,
интервал, повторы, провалы) плюс опциональные под конкретный алгоритм: `stability` и
`difficulty` для FSRS, `ease` для SM-2, `box` для Лейтнера, `streak` для зубрёжки.

Изначально планировался JSON-блоб под каждый алгоритм, но единая структура вышла проще:
переключение алгоритма на наборе не теряет прогресс, а состояние целиком проверяется
тестами вместо того, чтобы прятаться в строке.

**Сверка с эталоном.** FSRS-6 — порт py-fsrs, проверяемый не «на глаз», а 87 шагами
эталонных векторов, сгенерированных из самой py-fsrs (`Core/Tests/.../fsrs6-vectors.json`).
Планирование повторений невозможно оценить визуально: интервал «вроде вырос» ничего не
доказывает. Любое расхождение с эталоном считается ошибкой порта.

## Импорт

Претендент №1 по простоте: файл `.json` формата из [deck-format.md](deck-format.md),
приложение регистрирует свой UTType и появляется в шторке «Поделиться».
Пути доставки с телефона: Файлы / iCloud Drive / Telegram → «Поделиться» → приложение.

Также поддержим вставку из буфера (скопировал JSON из чата с Claude → «Вставить набор»)
и CSV (term;translation;example) как запасной вариант.

Импорт обязан: валидировать по схеме, дедуплицировать по нормализованному `term`
(lowercase + trim), показывать превью «добавится 24 новых, 3 дубля пропущено» до применения.

## Бэкап

Экспорт всей базы в JSON — с первого дня, до любых красивостей. SwiftData-база может
поехать при миграции модели; единственная страховка — файл, который ты сам можешь положить
в iCloud Drive. Плюс автоэкспорт раз в неделю в фоне.
