# Промпт: подтянуть обучающее приложение до уровня «Карточек»

Скопируй текст ниже целиком в чат с ИИ-ассистентом вместе с доступом
к коду своего приложения.

---

Ты — ведущий разработчик и методист обучающих приложений. Перед тобой моё
приложение для обучения. Приведи его к принципам эталонного приложения,
описанного ниже, — по смыслу, а не копированием: мой предмет, аудитория
и стек могут отличаться.

Порядок работы:
1. Изучи код и опиши, что приложение делает сейчас.
2. Пройди по каждому разделу эталона и отметь: «уже есть», «есть частично»,
   «нет», «не нужно моему приложению — потому что…».
3. Составь план по итерациям: сначала то, что сильнее всего влияет на
   результат ученика, потом удобство, потом украшения. Для каждой задачи —
   зачем она, объём и риск.
4. Реализуй план по одной итерации. Каждая итерация: код, тесты и запись
   о решениях.
5. Спроси меня, прежде чем менять архитектуру, хранилище данных или платные
   сервисы.

## Эталон

### 1. Главный цикл, ради которого всё существует
Ученик потребляет живой материал (серию, статью, урок) → воспроизводит его
своими словами (пересказ вслух) → получает разбор: что понял верно, что
исказил, какие ошибки в языке → ошибки одной кнопкой становятся карточками →
карточки повторяются по расписанию → следующий пересказ лучше.
Каждая фича оценивается по тому, насколько она усиливает этот цикл.
Карточки — средство, а не цель.

### 2. Интервальное повторение
- Выбор алгоритма на уровне набора: FSRS (по умолчанию, со сверкой по
  эталонным векторам py-fsrs), SM-2, коробки Лейтнера, зубрёжка.
- Несколько типов карточек из одной записи: узнавание, воспроизведение,
  на слух, правописание, произношение, пропуск в предложении.
- Проверка ввода прощает регистр, артикли и одну опечатку. Карточки
  правописания — не прощают.
- Лимиты новых карточек и повторов в день: после пропуска ученик получает
  обычный день, а не завал из четырёхсот карточек.
- Карточки одного слова разносятся по разным дням.
- Учебный день кончается в 4 утра: ночная сессия не рвёт счёт дней.
- «Пиявки»: карточки, забытые N раз, собираются отдельно, и к каждой —
  конкретный совет, что с ней делать.
- Интервал показан прямо на кнопке оценки.

### 3. Материалы: без ручного труда, но с контролем
- Набор делает ИИ по короткому запросу («Friends 1x03») с учётом уровня
  ученика. Ответ приходит по JSON-схеме (structured outputs), поэтому всегда
  разбирается.
- С приложенными субтитрами примеры — настоящие реплики. Без субтитров
  примеры обычные и не выдаются за цитаты: выдуманные цитаты — главный риск
  ИИ-контента.
- Импорт файлов терпим к формату: понимает синонимы полей, голый массив,
  markdown вокруг JSON. Строгая проверка — только по содержимому, с номером
  проблемной записи в сообщении.
- Перед записью в базу — всегда превью: что добавится, какие дубли, на что
  обратить внимание.
- В запросе к ИИ передаётся список слов, которые уже есть у ученика.

### 4. Разбор речи ученика
- Модель судит о содержании только по эталону (субтитрам), к каждому
  утверждению — цитата. Проверить нельзя — так и сказано, а не «ошибка».
- Вероятные ошибки распознавания речи помечаются и не ставятся ученику
  в вину.
- Понимание и качество языка — отдельно. Главных замечаний — не больше трёх.
- Тон спокойный и конкретный: что именно, где и как правильно.
- Стоимость запроса видна до отправки. Месячный лимит расходов общий для
  всех ИИ-функций. Расход записывается, даже если ответ не разобрался.

### 5. Мотивация, которая не врёт
- Метрика «выучено» — только слова, дожившие до длинного интервала
  (например, 21 день). Просмотры и клики не в счёт.
- Награды ученик назначает себе сам: «150 выученных слов — покупаю игру».
  Прогресс считается от момента создания цели. Правки руками помечаются.
- Серия дней с заморозками: 2 в месяц, не больше двух подряд. Заморозка
  тратится в день пропуска и не пересчитывается задним числом. Замороженные
  дни серию не рвут, но и в счёт не идут. Рядом — мягкая недельная цель.
- Достижений мало, и все — за результат.
- Сознательно нет: лиг, «жизней» и штрафов за ошибки, очков опыта за
  действия, случайных уроков, не связанных с материалом ученика.

### 6. Уровень ученика
Тест «знаю / не знаю» по словам из частотных полос вперемешку с выдуманными
словами. «Знаю» на выдумку снижает результат, «знаю на всё» даёт ноль.
Итог — примерный размер словаря и уровень CEFR. Уровень можно поправить
руками; от него зависит подбор материала (на ступень выше).

### 7. Знакомство при первом запуске
Не реклама, а настройка: каждый шаг что-то делает. Выбор языка
(по умолчанию — системный), объяснение главного цикла, тест уровня,
стартовый набор, проверка голоса, цель с наградой, время напоминания.
Уже ненужные шаги не показываются. Пропустить можно в любой момент.

### 8. Языки
- Интерфейс на нескольких языках. По умолчанию — язык системы, переключение
  в приложении мгновенное, без перезапуска.
- Язык интерфейса — он же язык переводов и объяснений ИИ.
- Каждая строка записана сразу на всех языках. Пропустить перевод не даст
  компилятор, а текст вне системы переводов ловит линтер.
- Склонения при числах — по правилам каждого языка («1 карточка, 2 карточки,
  5 карточек»).
- Инструкции для ИИ пишутся на английском, с указанием языка ученика.

### 9. Оформление
- На экране одно очевидное действие. Главная кнопка крупная и внизу, под
  большим пальцем.
- Цвет означает смысл (верно, ошибка, новое, зрелое), а не украшает.
- Главный экран — не список настроек, а карточки: сколько на сегодня,
  кнопка «Учить», серия, прогресс к награде. Пустое состояние — кнопки
  действия, а не инструкция мелким шрифтом.
- Единый стиль через общие компоненты: поверхность карточки, стиль кнопки,
  полоса прогресса, шрифт через одну функцию. Сейчас это пиксельное ретро:
  рамки со ступенчатыми углами, жёсткие тени, вдавливающиеся кнопки,
  пиксельный шрифт только для крупного, читаемый шрифт для текста.
- Контраст цветов проверен расчётом по WCAG. Поддержаны тёмная тема,
  Dynamic Type и «Уменьшение движения».
- Анимация запуска ничего не задерживает: полная раз в день, дальше
  короткая, пропускается касанием.

### 10. Инженерия
- Логика отделена от интерфейса в модуль без UI-фреймворков, который
  тестируется за секунды без симулятора.
- Тесты обязательны для алгоритмов, разбора форматов (включая битый ввод),
  работы с базой и любых формул прогресса и наград. Негативные случаи
  обязательны. Тесты базы — на базе в памяти.
- Статический линтер ловит типичные ошибки до сборки: скобки, импорты,
  непереведённые строки.
- Секреты (ключи API, строка подключения к базе) — только в защищённом
  хранилище (Keychain), никогда в коде, настройках или журнале.
- SQL — только с параметрами.
- Данные:
  - локально — источник правды, приложение работает без сети;
  - бэкап в файл раз в неделю;
  - восстановление одной транзакцией с откатом;
  - снимок в облачный Postgres (Neon) раз в сутки для переезда на новый
    телефон.
- Журнал событий внутри приложения, который можно переслать одним нажатием.
- Решения, влияющие на архитектуру, записываются с причинами.
- Конфиг ИИ-ревью (CodeRabbit) с правилами проекта.
