# Обновления сервера без поломок

_P-71. Главное правило: приложение в App Store обновляется не сразу и не у
всех. Сервер в любой момент обслуживает и новую, и старые версии — поэтому
всё, что меняется на сервере, должно работать с ними одновременно._

## Правила API

1. **Поля только добавляются.** Новое поле в запросе — необязательное, у
   старых версий его нет (`target`, `requestId`). Новое поле в ответе старые
   версии просто не читают. Убрать поле или сменить его тип нельзя.
2. **Контракт проверяется тестами с обеих сторон.** `schema/api/requests` —
   то, что шлёт приложение (ядро: `ContractTests`, сервер: `contract.test.ts`
   — принимает ли). `schema/api/responses` — настоящие ответы сервера; ядро
   проверяет, что их читает, а сервер — что не потерял ни одного поля.
3. **Несовместимое изменение — новый префикс** (`/v2/...`), `/v1` живёт, пока
   им пользуются.
4. **Старые версии отключаются явно.** `MIN_CLIENT_BUILD` в переменных Worker:
   сборки ниже получают 426 и экран «обнови приложение». Выгрузка, удаление
   данных и скачивание своих копий работают для любой версии.

## Правила базы

1. **Миграции только расширяют** (expand): новые таблицы, столбцы со
   значением по умолчанию, индексы. Тест `migrations.test.ts` не пропустит
   `DROP`, `RENAME` и обязательный столбец без `DEFAULT`.
2. **Удалять — в два релиза** (contract): сначала код перестаёт читать
   столбец, после деплоя и недели без откатов — отдельная миграция с
   первой строкой `-- contract: почему` убирает его.
3. **Миграция идёт до кода.** Старый код с новой схемой работает (пункт 1),
   поэтому между двумя шагами деплоя ничего не ломается.

## Деплой

Actions → **Deploy server** → staging, проверить приложение на тестовом
сервере, затем production (с подтверждением). Шаги: тесты → отметка Time
Travel → миграции → код → `/v1/health` должен показать новую версию.
Не показал — код откатывается сам (`wrangler rollback`).

Откат данных — только если миграция испортила данные (при правилах выше
такого быть не должно): `wrangler d1 time-travel restore recap --timestamp=…`
на отметку из журнала деплоя. Это вернёт и изменения людей за прошедшее
время — крайняя мера.

## Если что-то горит

- Сбоит модель или расход вышел из-под контроля: `DISABLED_FEATURES =
  "lesson,lesson_chat"` (или `"all"`) в переменных Worker — без выпуска
  приложения. Люди видят «на обслуживании», карточки работают офлайн.
- Сломалась новая версия кода: `wrangler rollback` — прошлая версия за секунды.
- Состояние: `GET /v1/health` — база, версия кода, последняя миграция,
  порог версии приложения, где лежат бэкапы.

## Хранилище

Снимки бэкапов пишутся в R2, если подключено (`[[r2_buckets]]` в
wrangler.toml), иначе в D1 кусками, как раньше. Старые снимки из D1
читаются и после подключения R2 — переезд без поломки, переносить ничего
не нужно: за неделю старые копии вытеснятся новыми.
