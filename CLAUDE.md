# Правила проекта

## Тесты обязательны

Любая новая логика приезжает вместе с юнит-тестами. Не «потом», не «когда стабилизируется» —
в том же коммите.

Что покрывать обязательно:
- **алгоритмы** (планировщики повторений, сравнение ответов, подсчёт «выученного»),
- **разбор и запись форматов** (наборы, бэкапы, субтитры) — включая битый и чужой ввод,
- **сервисы работы с базой** (импорт, экспорт, дедупликация, создание папок),
- **любую формулу, влияющую на прогресс или награды** — здесь ошибка невидима глазом
  и обнаружится через месяц испорченной статистики.

Что можно не покрывать: верстку экранов SwiftUI и обёртки над системными контролами.

### Куда класть

| Тесты | Где | Как гонять |
|---|---|---|
| Логика без Apple-фреймворков | `Core/Tests/AJFMCoreTests/` | `cd Core && swift test` — секунда, без симулятора |
| Работа с базой, SwiftData | `App/Tests/` | ⌘U в Xcode |
| Сервер (подписка, промокоды, лимиты) | `backend/test/` | `cd backend && npm test` — на настоящем SQLite |

**Логику по умолчанию писать в `Core/`**, а не в приложении. Всё, что живёт там,
тестируется мгновенно и без Xcode — значит, будет тестироваться на самом деле.
В `App/` остаётся только то, что без SwiftData и SwiftUI не работает.

### Как писать

- Один тест — одно утверждение о поведении. Название говорит, что проверяется.
- Обязательно негативные случаи: битый JSON, пустые поля, неизвестные значения,
  дубли, деление на ноль, пустая база.
- Для алгоритмов повторений — сверка с эталонными векторами (py-fsrs), а не
  «проверим, что интервал вырос».
- Тесты базы работают на `ModelConfiguration(isStoredInMemoryOnly: true)` — никаких
  следов на диске между запусками.

### Перед коммитом

```sh
python3 tools/lint.py
```

Статические проверки без компилятора: баланс скобок, пропущенные импорты,
публичные структуры без `public init`, дубликаты типов. Не заменяют сборку,
но ловят ровно те ошибки, которые чаще всего всплывают, когда код пишется
без Xcode.

## Навыки для iOS-кода

В `.claude/skills/` — правила, собранные из открытых источников и подогнанные
под проект. Перед работой над экранами и перед ревью — открывать нужный:

| Навык | Когда |
|---|---|
| `ios-architecture` | любой экран, ViewModel, навигация, превью — **главные правила**: `@Observable`, `NavigationStack` + `NavigationPath`, View без логики, `private struct Previews: View` с mock-данными |
| `swiftui-review` | написание и ревью SwiftUI: устаревшие API, данные, доступность, iPad и iPhone Duo |
| `ios-polish` | анимации, отклик, пустые состояния, виджет, чат с Мончиком, камера |
| `ios-verify` | перед коммитом и после пуша: lint, тесты, CI, прогон на устройствах |
| `secure-testing` | тесты для доступа, денег, ключей, чужих файлов, сети и звука; прерывания; гигиена тестов |

Агенты в `.claude/agents/` — запускать после заметной правки, до коммита:

| Агент | Зачем |
|---|---|
| `code-reviewer` | независимое ревью кода, написанного другим агентом: несуществующие API, неполные миграции, тихие ошибки, тесты-пустышки; только уверенные находки |
| `security-reviewer` | ревью безопасности изменений приложения и сервера: доступ, деньги, секреты, SQL, хранение, чужие файлы |

Часть правил проверяет `tools/lint.py`: превью в каждом экране, никаких
`ObservableObject` / `NavigationView`, `@MainActor` у `@Observable`.
