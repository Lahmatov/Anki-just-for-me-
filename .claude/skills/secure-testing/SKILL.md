# Безопасное тестирование

Собрано из [OWASP MASTG](https://mas.owasp.org/MASTG/) (тесты мобильных
приложений), правил ревью безопасности Anthropic
([claude-code-security-review](https://github.com/anthropics/claude-code-security-review), MIT)
и навыков [Trail of Bits](https://github.com/trailofbits/skills) (`differential-review`,
`sharp-edges`, `insecure-defaults`, `property-based-testing`; CC BY-SA 4.0) —
пересказ под этот проект. Общие правила тестов — `CLAUDE.md`; модель
угроз — `docs/security.md`.

## 1. Гигиена тестов — всегда

- **Никаких настоящих секретов.** Ключи, токены, перцы — выдуманные и явно
  тестовые (`"sk-test"`, `"test-pepper-…"`, как в `backend/test/helpers.ts`).
  Настоящий ключ в фикстуре — утечка в историю git навсегда.
- **Никаких настоящих людей.** В фикстурах — `anna@example.com`, а не чья-то
  почта; без реальных имён, телефонов, Apple ID.
- **Без сети.** Внешние службы — подделки (`fakeFetch`, `FakeClaude`, `FakeR2`);
  тест, который ходит в интернет, нестабилен и может отправить данные наружу.
- **Без следов.** База — `ModelConfiguration(isStoredInMemoryOnly: true)` /
  SQLite в памяти; Keychain и UserDefaults в тестах — отдельные ключи или
  очистка в `tearDown`.
- **Продакшен-код не ослабляется ради теста.** Никаких `#if DEBUG`, которые
  отключают проверку подписи, доступа или лимитов. Подменяется зависимость
  (`Deps`, протокол, параметр), а не проверка. Флаги UI-тестов (`UITesting`)
  меняют данные и анимации, но не безопасность.
- **Детерминизм.** Время — через параметр (`now:`), случайность — через
  `randomBytes`/зерно. Тест, который иногда падает, — это недоказанный баг.

## 2. Обязательные тесты по зонам риска

Риск определяется тем, что код трогает, а не размером правки («два
изменённых знака» — тоже повод, Heartbleed был в двух строках).

| Зона | Обязательные случаи |
|---|---|
| **Доступ** (`authenticate`, `requireAdmin`, вход через Apple) | без токена → 401; чужой/битый токен → 401; токен устройства не открывает служебный вход; данные устройства A недоступны устройству B; удалённое устройство → 401 |
| **Деньги и лимиты** (подписка, промокоды, квоты) | повтор с тем же номером запроса не списывает дважды; исчерпанная квота → 402; истёкший доступ → 402; подбор промокода упирается в лимит; подделанная транзакция не активирует |
| **Секреты** | секрет не попадает в ответ, журнал (проверяет `tools/lint.py`), обращение в поддержку; неверный секрет и секрет неверной длины — одинаковый отказ |
| **SQL** | ввод с кавычками и `--` в каждом поле сохраняется как текст, а не выполняется |
| **Чужие файлы** (наборы, бэкапы, субтитры, PDF, ответы ИИ) | битый JSON, пустые поля, неизвестные значения, огромный размер, лишние поля, неверный формат (`RCB1`), путь с `../` — понятная ошибка, а не падение и не запись мимо |
| **Хранение на телефоне** | токены и ключи — Keychain с `WhenUnlockedThisDeviceOnly`; в UserDefaults и файлах их нет; «Удалить все данные» стирает всё (тест на базе в памяти) |
| **Удаление и выгрузка** | после удаления — ни записи, ни объекта в R2; выгрузка совпадает с тем, что сервер хранит; один код поддержки на два устройства — отказ |
| **Сеть** | 401 → новая регистрация один раз; 426 → «обновите приложение»; 503 `feature_disabled` → «на обслуживании»; обрыв идемпотентного запроса → один повтор; неидемпотентного → без повтора; нет сети → «нет интернета» без повтора |
| **Звук** | звонок, отключённая гарнитура, смена микрофона, уход в фон во время записи → запись остановлена, сказанное сохранено, микрофон не включается сам (`AudioInterruptionPolicy`) |

Каждой исправленной уязвимости — **регрессионный тест**, названный по сути:
`testDeviceTokenDoesNotOpenAdmin`, а не `testFix123`.

## 3. Свойства вместо примеров — для разборщиков

Для кода, который превращает одно в другое (разбор наборов и бэкапов,
нормализация слов, кодирование API, сжатие), один пример доказывает мало.
Проверяй свойство на многих входах (цикл по сгенерированным данным с зерном):

| Свойство | Формула | Где у нас |
|---|---|---|
| Туда-обратно | `decode(encode(x)) == x` | `DeckParser`, бэкап `RCB1`, `BackendAPI` тела |
| Идемпотентность | `f(f(x)) == f(x)` | `TermNormalizer`, нормализация кода поддержки |
| Инвариант | держится до и после | расписание FSRS (интервал ≥ 0), квота не уходит в минус |
| Оракул | `new(x) == reference(x)` | FSRS против эталонных векторов py-fsrs |

Два способа написать тест, который ничего не проверяет: **тавтология**
(ожидание считается тем же кодом, что проверяется) и **пустота** (фильтр
отбрасывает почти все входы). Ни того, ни другого.

## 4. Прерывания и плохая сеть — ручная проверка на устройстве

Симулятор не умеет входящий звонок. Перед выпуском — на телефоне:

1. Пересказ: начать запись → позвонить себе с другого телефона → после звонка
   текст сохранён, видна плашка «запись остановилась», микрофон выключен.
2. Произношение: во время записи слова выдернуть наушники → оценка по сказанному.
3. Озвучка карточки → выдернуть наушники → тишина, а не динамик на весь вагон.
4. Набор через сервер → свернуть приложение на 30 секунд → вернуться → набор
   продолжился сам (`NetworkInterruption`).
5. Авиарежим → «Набор через Claude» → «Нет интернета…», без вечного загрузчика.
6. Настройки → Разработчик → Network Link Conditioner «Very Bad Network» →
   набор и разговор: понятная ошибка или повтор, не зависание.
7. Переключение Wi-Fi → сотовая посреди запроса → один тихий повтор.

## 5. Ревью тестов

- Тест падает, если сломать проверяемое поведение? Проверь мысленно: убери
  проверку в коде — какой тест покраснеет? Ни один — тест бесполезен.
- Есть негативный случай на каждую позитивную ветку доступа.
- Нет `sleep` ради времени — время подставляется.
- Агент-ревьюер безопасности — `.claude/agents/security-reviewer.md`;
  ревьюер кода другого агента — `.claude/agents/code-reviewer.md`.
